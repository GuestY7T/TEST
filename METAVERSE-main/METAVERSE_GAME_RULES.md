# METAVERSE Game Rules

1. METAVERSE is a platform containing multiple games and experiences.
2. Games can be official METAVERSE experiences or creator-made experiences.
3. Each game can have its own gameplay rules and identity.
4. Game-specific rules must not violate platform-wide security, privacy, accessibility, or authority requirements.
5. Game Owner, Creator/Developer, and Game Admin roles are scoped to the individual game.
6. Game permissions must be explicit, auditable, and revocable.
7. Important multiplayer/gameplay state must be authoritative and validated.
8. Clients may predict for responsiveness, but client state is never automatically authoritative.
9. Validate important client actions and network requests.
10. Creator code must remain inside the approved sandbox.
11. Games must not bypass METAVERSE security or permission systems.
12. Game transactions must use the approved marketplace/escrow architecture.
13. Creator content must respect copyright and required permissions.
14. Accessibility is part of the game experience.
15. Reduced Motion and accessibility settings should be respected.
16. Graphics/performance scaling changes presentation, not authoritative gameplay truth.
17. Hardware/input capabilities should determine appropriate controls and presentation.
18. METAVERSE adapts to the device, not the other way around.
19. Games should have recovery behavior for important failures where practical.
20. Publishing requires appropriate quality checks.
21. A prototype is not automatically a finished game.
22. Never claim a feature is implemented unless it actually exists and has been tested.
23. Major implementations should pass BIG CHECK and ULTRA CHECK.
24. METAVERSE games should have original identities and must not copy protected assets/content from other games.
25. BlockWorld is an original METAVERSE voxel/block-building game.
26. Pulse Arena is the approved name for the former gun-game concept.
27. METAVERSE supports games such as racing, paintball, tournaments, puzzle worlds, arenas, mini-game hubs, and creator-made experiences.
28. Games can connect to METAVERSE's larger world/exploration system.
29. Players should be able to explore, create, play, and return to experiences.
30. Banana has final approval over official METAVERSE game features.
31. Prioritize fun gameplay, exploration, creation, friends/multiplayer, replayability, smooth UX, and a distinct METAVERSE identity.
32. Follow the development loop: Research -> Build -> Improve -> Test -> Improve again.
33. Do not add METAVERSE Connect or Connect Studio features to the game unless Banana explicitly approves that integration.
34. Keep game systems modular so individual experiences can evolve without breaking the whole platform.
35. Make the game awesome.
